# BMG Omsk Crew - стратегия переводов

Этот документ описывает, как добавлять и поддерживать переводы в приложении, чтобы не плодить дубли, не ломать поиск и не смешивать разные типы текстов. Перед правками переводов сначала прочитай этот файл и `docs/PROJECT_GUIDE.md`.

## Главный принцип

Перевод в проекте делится на несколько слоев. Не надо искать "одно место для всего": UI, названия трейтов, длинные правила, Objective-карты и PDF-материалы переводятся разными механизмами.

Общее правило:

- короткие элементы интерфейса переводятся через UI-словари;
- названия, трейты, ранги, фракции и оружейные свойства переводятся через display-словарь и паттерны;
- длинные правила переводятся по точному английскому тексту с нормализацией;
- Objective-карты переводятся в данных карты или через официальный override-файл;
- PDF не является runtime-источником переводов, если отдельно не делается перевод PDF.

## Кодировка

Все новые документы и правки переводов писать в UTF-8.

PowerShell может показывать кириллицу как mojibake, даже если файл нормальный. Для проверки чтения используй:

```powershell
$OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
Get-Content -Encoding UTF8 -Path docs\TRANSLATION_STRATEGY.md -TotalCount 20
```

Не делай массовую перекодировку существующих файлов без отдельной проверки в браузере. Особенно осторожно с `official-card-translations.js`: там уже есть исторические OCR/кодировочные артефакты.

## Где лежат переводы

### 1. Основной UI

Файл: `script.js`

Словарь:

- `translations.ru`
- `translations.en`

Используется через:

- `t(key, params)`
- HTML-атрибуты `data-i18n`
- `data-i18n-title`
- `data-i18n-placeholder`
- динамические сообщения, warning/notice, кнопки и статусы

Когда добавлять сюда:

- новый пункт меню;
- текст кнопки;
- заголовок секции;
- placeholder;
- warning/notice;
- статус в билдере, турнире, матче;
- любой текст, который должен переключаться RU/EN и относится к интерфейсу.

Правило: если добавил ключ в `ru`, добавь и в `en`. Не оставляй английский ключ без пары.

Пример:

```js
translations.ru.my_new_key = "Новый текст";
translations.en.my_new_key = "New text";
```

В реальном коде добавляй ключи внутри существующих объектов, а не через присваивание.

### 2. Локальные подписи карточки модели и экипировки

Файл: `script.js`

Словарь:

- `localizedUi.ru`
- `localizedUi.en`

Используется через:

- `uiText(key)`

Когда использовать:

- подписи в full-card модели;
- подписи модалки экипировки;
- локальные labels вроде `section_traits`, `section_equipment`, `available_rep`.

Правило: если текст шире, чем full-card/equipment UI, лучше добавлять в общий `translations`.

### 3. Фракции и ранги

Файл: `script.js`

Словари:

- `factionLabels`
- `rankLabels`

Функции:

- `localizeFactionList(...)`
- `localizeRank(...)`

Когда добавлять:

- новая фракция;
- официальный вариант имени фракции;
- переименование фракции в UI;
- новый ранг.

Важно: ключом обычно остается официальный английский текст. Русское отображение добавляется как `ru`.

### 4. Короткие названия и UI-display текст

Файл: `script.js`

Основные словари:

- `exactTextTranslations`
- `exactTraitTranslations`
- `exactWeaponTraitTranslations`
- `displayGlossary`

Основная функция:

- `translateDisplayText(text)`

Паттерны:

- `translateTokenWithPatterns(...)`
- regex-паттерны для трейтов вида `Minion (3)`, `Elite (SWAT)`, `Lieutenant (Bane)`, `Duo (Sugar)` и т.п.

Когда добавлять сюда:

- название экипировки;
- название трейта;
- название weapon trait;
- короткий термин, который встречается в разных местах;
- новый шаблон трейта с параметром.

Стратегия:

- если это точный короткий термин, добавь в exact-словарь;
- если это семейство терминов с параметром, добавь regex-паттерн;
- если это общий игровой термин, добавь в glossary, но осторожно: glossary может менять текст шире, чем ожидается.

Не переводи имена моделей через glossary. Имена моделей обычно остаются как в официальных данных, иначе ломается поиск, импорт и сопоставление Objective-карт.

### 5. Длинные тексты правил Compendium

Файл: `script.js`

Словари и функции:

- `exactCompendiumBodyTranslations`
- `normalizeTranslationKey(text)`
- `normalizedCompendiumBodyTranslations`
- `normalizedCompendiumBodyFallbacks`
- `translateCompendiumBody(...)`

Когда добавлять сюда:

- полный текст трейта;
- полный текст специального правила;
- длинный официальный текст из `traitDescriptions` в `data.js`;
- исправление плохого или неполного перевода правила.

Стратегия:

1. Берем английский текст из `data.js` / `traitDescriptions` / official source.
2. Добавляем перевод в `exactCompendiumBodyTranslations.ru`.
3. Для многострочного или нестабильно отформатированного текста используем ключ через `normalizeTranslationKey("...")`.
4. Сохраняем игровые иконки `{STUN_ICON}`, `{RANK_HENCHMAN_ICON}` и другие токены без изменения.
5. Не меняем исходный английский текст в `data.js`, если задача только про перевод.

Почему так: `data.js` должен оставаться локальной базой официальных/синхронизированных данных, а перевод длинных правил лучше держать отдельным слоем.

### 6. Objective-карты

Файлы:

- `data.js`
- `official-card-translations.js`
- иногда `script.js` для рендера

Функции:

- `getLocalizedCardField(value)`
- `renderLocalizedCardText(value)`
- `renderBuilderCardText(card)`
- `showBuilderCardTranslation(cardKey)`
- `showBuilderCardPreview(card)`

Типы хранения:

1. Поле уже может быть объектом:

```js
text: { en: "...", ru: "..." }
resource: { en: "...", ru: "..." }
```

2. Для официальных карт используется override по id в `official-card-translations.js`.

Когда добавлять куда:

- если карта уже локально описана в `data.js` и правка точечная, можно добавить/поправить `text.ru` или `resource.ru`;
- если это официальная карта из official sync, предпочтительно добавлять перевод в `official-card-translations.js`;
- если перевод получен из OCR изображения карты, помечай источник через существующую схему `translationSource`, если она применима;
- если полного перевода нет, не оставляй в UI заглушку "смотри на изображении", когда пользователь просит перевести - добавь текстовый перевод.

Важно:

- сохраняй структуру "Условие / Ресурс / Усиление / VP" если она есть;
- не теряй `Burn`, `Trap`, `Limited`, `Task`, фазы и значения;
- не переводи название карты, если оно используется как ключ поиска/сопоставления.

### 7. Encounter/Event карты

Файл: `script.js`

Данные:

- `MATCH_SETUP_CARDS`

Карты обычно уже имеют поля:

```js
text: {
  en: "...",
  ru: "..."
}
```

Когда добавлять:

- новые Encounter/Event карты;
- перевод текста деплоя/ивента;
- исправление формулировки.

Проверять в:

- раздел `Правила` -> `Деплой / Ивенты`;
- режим `Матч`;
- режим `Игра`, где можно выбрать или сгенерировать setup-карты.

### 8. PDF и внешние правила

PDF-файлы лежат вне runtime-словарей. Они используются как источник правил и как документы для открытия.

Стратегия:

- если пользователь просит "переведи PDF", делай отдельный переведенный PDF или текстовый артефакт;
- если пользователь просит "добавь поиск по правилам", извлекай нужные тексты в локальные данные приложения;
- если из PDF берется правило для приложения, добавляй его в соответствующий локальный справочник, а не делай приложение зависимым от чтения PDF на лету.

## Терминологическая стратегия

Проект использует гибридный русский перевод. Часть BMG-терминов остается на английском, потому что так проще сверяться с официальными картами и правилами.

### Обычно переводим

- интерфейсные слова: добавить, удалить, поиск, доступно, найдено;
- ранги в UI: Leader -> Лидер, Sidekick -> Сайдкик;
- фракции в UI: Bat Family -> Семья Бэтмена;
- описательные глаголы: gains -> получает, choose -> выберите;
- общие слова: weapon -> оружие, equipment -> экипировка.

### Обычно оставляем на английском

- имена моделей;
- названия Objective-карт;
- ключевые игровые термины без стабильного русского аналога;
- `Objective`, `Suspect`, `Effort`, `Audacity`, `VP`, `REP`, `Funding`;
- статусы, если они как официальные keywords: `KO`, `Casualty`, `Enervating`, `Hypnotize`, `Poison`, `Scared`, `Terror`;
- названия фаз, если они используются как ключ: `Raise the Plan`, `Execute the Plan`, `Recount`.

### Иконки и токены

Никогда не переводить и не менять токены:

- `{STUN_ICON}`
- `{BLOOD_ICON}`
- `{RANK_HENCHMAN_ICON}`
- `{SPECIAL_ICON}`
- `{OT_CONTROL_ICON}`
- `{+ATT_ICON}`
- любые похожие `{..._ICON}`

Они обрабатываются `replaceIcons(...)`. Если токен сломать, вместо иконки появится текст или пустота.

## Процесс добавления перевода

1. Определи тип текста:
   - UI?
   - короткий термин?
   - название трейта?
   - длинное правило?
   - Objective-карта?
   - Encounter/Event?
   - PDF?

2. Найди правильный слой по разделам выше.

3. Добавь перевод максимально локально:
   - UI -> `translations`;
   - full-card/equipment labels -> `localizedUi`;
   - term/trait/weapon -> exact/pattern dictionaries;
   - long rule -> `exactCompendiumBodyTranslations`;
   - Objective -> card field or `official-card-translations.js`;
   - setup card -> `MATCH_SETUP_CARDS`.

4. Сохрани исходные ключи на английском.

5. Не меняй official ids, names, aliases, card names и model names ради перевода.

6. Проверь RU и EN.

## Как исправлять плохой перевод

### Плохой короткий термин

Исправь exact-словарь:

- `exactTextTranslations`
- `exactTraitTranslations`
- `exactWeaponTraitTranslations`

Если термин переводится только внутри одного длинного текста, лучше править длинный перевод, а не glossary.

### Плохой длинный текст трейта

1. Найди английский текст в `data.js` / `traitDescriptions`.
2. Найди его ключ в `exactCompendiumBodyTranslations` или fallback.
3. Правь русский текст там.
4. Если ключ не находится из-за переносов строк, добавь ключ через `normalizeTranslationKey(...)`.

### Плохой текст Objective-карты

1. Найди карту по official id, name или изображению.
2. Если перевод лежит в `official-card-translations.js`, правь там.
3. Если перевод лежит прямо в `data.js`, правь `text.ru` / `resource.ru`.
4. Проверь предпросмотр карты в билдере и режиме игры.

## Что не делать

- Не переводить `name`, `officialName`, `officialAlias`, `id`, `matchName`, если это не отдельная задача по отображению. Эти поля участвуют в поиске и сопоставлении.
- Не переводить икон-токены `{...}`.
- Не делать массовую замену английских терминов по всему `data.js`.
- Не смешивать UI-ключи и длинные правила в одном словаре.
- Не добавлять один и тот же перевод одновременно в `data.js`, `script.js` и `official-card-translations.js`.
- Не удалять английский оригинал.
- Не полагаться только на текстовую проверку: длинный перевод может сломать карточку визуально.

## Проверки после перевода

Минимальная синтаксическая проверка:

```powershell
& 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --check script.js
```

Если менялся `official-card-translations.js`, проверь его тоже:

```powershell
& 'C:\Users\user\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\bin\node.exe' --check official-card-translations.js
```

Ручная проверка в браузере:

- переключить RU/EN;
- открыть меню и основные разделы;
- открыть билдер;
- открыть full-card модели с переведенным трейтом;
- открыть popup трейта;
- открыть карточки Objective в билдере;
- открыть предпросмотр карты;
- открыть режим игры и предпросмотр карты там;
- открыть `Правила` и поиск по правилам;
- проверить мобильную ширину, если перевод длинный.

## Визуальная длина текста

Русский текст часто длиннее английского. После перевода особенно проверяй:

- кнопки;
- чипы фильтров;
- бейджи статуса;
- compact panels в билдере;
- карточки Objective в мобильном виде;
- popup трейтов;
- турнирный чек-лист;
- верхнюю панель builder/match.

Если текст не помещается:

- сокращай UI-label;
- переноси подробность в tooltip/popup/status line;
- не уменьшай шрифт глобально;
- не добавляй текст-инструкции внутрь компактных кнопок.

## Рекомендуемый глоссарий

Сохранять как есть:

- Objective
- Objective deck
- Suspect
- Effort
- Audacity
- VP
- REP
- Funding
- KO
- Casualty
- LoS
- Range
- Trait
- Rank
- Boss
- Leader / Sidekick / Henchman / Free Agent, если это часть официального правила, а не UI-label

Переводить в обычном тексте, если не ломает смысл:

- friendly model -> дружественная модель
- enemy model -> вражеская модель
- choose -> выберите
- place/set -> разместите
- draw -> возьмите карту
- discard -> сбросьте
- score -> выполните / засчитайте
- remove as Casualty -> удалите как выбывшую
- gains the rule/trait -> получает правило/трейт
- within X" -> в пределах X"

Спорные термины лучше оставлять английскими, если они являются ключевым словом карты или правила. Консистентность важнее полного перевода.

## Когда создавать отдельный файл переводов

Создавать отдельный файл стоит, если:

- переводов много;
- они относятся к одному источнику;
- их неудобно поддерживать внутри `script.js`;
- они не должны смешиваться с логикой.

Пример уже есть: `official-card-translations.js`.

Возможные будущие кандидаты:

- `official-trait-translations.js` для больших переводов трейтов;
- `rules-search-translations.js` для текстов поиска по правилам;
- `pdf-translations/` для переведенных PDF-артефактов.

Но не начинай выносить существующие словари без отдельной задачи на рефакторинг.

## Текущая рекомендация для будущих правок

Для обычной задачи "переведи X" действуй так:

1. Если X - карта Objective, сначала ищи в `official-card-translations.js`.
2. Если X - трейт или правило модели, сначала ищи `exactCompendiumBodyTranslations`.
3. Если X - короткое название трейта, ищи `exactTraitTranslations` и pattern translations.
4. Если X - кнопка/экран/статус, ищи `translations`.
5. Если X - подпись full-card/equipment, ищи `localizedUi`.
6. Если X - PDF, делай отдельный перевод PDF/текста и только потом решай, нужно ли добавлять его в приложение.
